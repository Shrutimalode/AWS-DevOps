# 🪣 S3 (Simple Storage Service)

- It comes under the **Storage** category.
- It is one of the **storage services** provided by AWS.
- S3 provides **scalable storage**.
- In S3, files are stored in the form of **objects**.
- S3 is a **global service**.
- Objects are stored in **S3 buckets**.

---

## 🪣 Buckets & Objects

### Bucket

- Buckets are the **containers for the data** stored in S3.

### Objects

- Objects are the **fundamental entities stored in S3**.
- Files uploaded to an S3 bucket are stored as objects.

---

# ⚖️ EBS vs S3

## 💾 EBS (Elastic Block Store)

- It provides storage for **EC2**.
- It is a **block-level storage**.
- It is **Availability Zone specific**.
- The maximum volume capacity is **64 TB**.
- It is used for **small-scale applications**.

## 🪣 S3 (Simple Storage Service)

- It is an **independent service**.
- It is **object storage**.
- It is a **global service**.
- It provides **unlimited storage**.
- It is used for **large-scale applications**.

> **Note:** The maximum object size should not be more than **50 TB**.

---

# 🪣 Steps to Create a Bucket

1. Go to **S3** → Click on **Create Bucket**.
2. Give the bucket name according to the naming rules.
   - The bucket name must be **unique**.
3. Go with the **default options**.
4. Click on **Create Bucket**.

---

# 📤 Steps to Upload a File / Object

1. Get inside the bucket.
2. Upload the object.
3. Click on the **Upload** button.

> ⚠️ **Note:** Before deleting the bucket, make sure you **empty the bucket**.

---

# 🌐 Steps to Host a Static HTML Page Using S3 Bucket

1. Create a bucket with **ACLs enabled**.
2. Uncheck **Block all public access**.
3. Acknowledge the changes.
4. Click on **Create Bucket**.
5. Upload the `index.html` page.
6. Once the object is uploaded:
   - Copy the **Object URL**.
   - Paste it into the browser.
   - You will get an **Access Denied** error.
7. Go to **Permissions** → Under **ACLs**, click **Edit**.
8. Give **Read** permission for the object.
9. Click on **Save Changes**.
10. Refresh the page where you pasted the Object URL to access the `index.html` page.

---

# 🌍 Steps to Perform Static Web Hosting Using S3

1. Create a bucket.
2. Go to **tooplate.com** in the browser and download the template.
3. Extract the files that you have downloaded.
4. Get inside the bucket and upload the files and folders.
5. Click on the **Upload** button.
6. Go to **Properties** → Scroll to the bottom → Click on **Edit Static Website Hosting**.
7. Change it to **Enable** → Click on **Save Changes**.
8. Copy the **Endpoint** and paste it into the browser.
   - You will get an **Access Denied** error.
9. Go to the browser and search for **AWS Policy Generator**.
10. Click on the first link.
11. Select **S3 Policy**.
12. In **Principal**, enter `*`.
13. Under **Actions**, select **Get Object**.
14. Give the **ARN (Amazon Resource Name)**.

   ```text
   arn:aws:s3:::<bucket-name>/*

```
15. Click on **Add Statement**.
16. Click on **Generate Policy**.
17. Copy the generated **JSON policy**.
18. Paste it into the **Bucket Policy**.
19. Click on **Save Changes**.
20. Refresh the page.

# 🔄 Bucket Versioning

**Bucket Versioning** means having multiple variants/versions of the objects in the same bucket.

It allows you to keep different versions of an object instead of completely replacing the previous version.

---

# 🔁 Bucket Replication

In S3, **Bucket Replication** is a feature that automatically copies objects from one bucket (**Source Bucket**) to another bucket (**Destination Bucket**).

- **Source Bucket** → Bucket where the original objects are uploaded.
- **Destination Bucket** → Bucket where the copies of the objects are stored.

---

# 🔄 Steps to Perform Bucket Replication

1. Create **2 buckets** by enabling the **Bucket Versioning** option.
   - One bucket will be the **Source Bucket**, where we upload the objects.
   - The second bucket will be the **Destination Bucket**, where the copies will be stored.

2. Go to **Management** in the Source Bucket.

3. Click on **Create Replication Rule**.

4. Give the **Replication Rule Name**.

5. Browse S3 and select the **Destination Path**.

6. Create a **new IAM role**.
   - This role allows access to objects from one bucket to another bucket.

7. Check whether the **Bucket Replication** option has been enabled.

8. If replication is enabled, upload objects inside the **Source Bucket**.

9. The uploaded objects will also be reflected in the **Destination Bucket**.
