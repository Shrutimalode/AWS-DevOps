# 🔐 AWS IAM (Identity and Access Management)

## 📌 What is IAM?

**IAM (Identity and Access Management)** is an AWS service used to securely manage access to AWS resources.

It allows you to create and manage:

- Users
- User Groups
- Policies
- Roles

IAM defines **who can access what resources and what actions they are allowed to perform** within an AWS account.

### Key Points

- IAM comes under **Security, Identity, and Compliance**.
- IAM is an **AWS web service**.
- IAM is a **global service**.
- IAM is used to manage **users, user groups, policies, and roles**.
- IAM helps implement **authentication and authorization** in AWS.

---

## 👤 Users

An **IAM User** is an identity created within an AWS account.

A user can have long-term credentials and can be used to interact with AWS resources.

### Example

Suppose an AWS account has three employees:

```text
AWS Account
    │
    ├── Manav
    ├── Shivani
    └── Veeresh
```
 - Each employee can have a separate IAM user with appropriate permissions.

# 🛠️ Steps to Create an IAM User

1. Go to the **IAM** service in the AWS Management Console.
2. Click on **Users**.
3. Click **Create user**.
4. Enter the **Username**.
5. Select **Provide user access to the AWS Management Console**.
6. Select **Custom password**.
7. If required, uncheck the option to require the user to create a new password at the next sign-in.
8. Click **Create user**.
9. Copy the **AWS Management Console sign-in URL**.
10. Open the sign-in URL in a new browser window.
11. Enter the IAM user's **username and password** to sign in.

> ⚠️ **Note:** In real-world environments, follow your organization's security policies. Avoid sharing passwords or credentials directly.

# 📜 IAM Policies

An **IAM Policy** is a document that defines permissions.

Policies specify:

- What actions are allowed or denied
- Which AWS resources can be accessed
- Under what conditions access is allowed or denied

## Types of IAM Policies

There are three commonly discussed policy types:

### 1. AWS Managed Policies

- Created and managed by AWS.
- Can be attached to multiple users, groups, or roles.
- AWS manages updates to these policies.

**Example:**

```text
AmazonS3ReadOnlyAccess
```
### 2. Customer Managed Policies

- Created and managed by the AWS customer.
- Can be customized according to the organization's requirements.
- Can be reused across multiple identities.

### 3. Inline Policies

- Directly embedded into a single user, group, or role.
- Maintained as part of that specific identity.
- Useful when permissions should be tightly associated with one identity.


# 👑 Root User

The **AWS Root User** is the identity created when an AWS account is first created.

The Root User has **complete access to the AWS account**.

### Example

```text
AWS Account
Account ID: 12345
     │
     ├── Root User
     │
     ├── Manav
     ├── Shivani
     └── Veeresh
```

## Root User vs IAM User

| Root User | IAM User |
|---|---|
| Created when AWS account is created | Created by an administrator |
| Has complete access to the AWS account | Permissions depend on attached policies |
| Should not be used for everyday tasks | Used for regular AWS activities |
| Cannot be restricted using IAM policies | Can be assigned specific permissions |

🔐 Best Practice: Do not use the Root User for everyday AWS tasks. Enable MFA on the Root User and use IAM identities or appropriate roles for regular access.




# 🔑 Authentication vs Authorization

IAM handles both **authentication** and **authorization**.

## Authentication

Authentication verifies **who you are**.

```text
Username + Password
        ↓
   Authentication
        ↓
     Identity
```

## Authorization

Authorization determines what you are allowed to do.

```text
Authenticated User
        ↓
      Policy
        ↓
  Allowed / Denied
        ↓
   AWS Resource
```
